# LinkedIn 템플릿

LinkedIn은 전문성과 관점을 짧게 보여주는 채널입니다.

참고한 실제 글:

- AI를 활용하는 것 vs AI에 의존하는 것
- 메타가 몰트북을 인수한 진짜 이유
- AI 엔지니어링의 무게중심이 바뀌고 있습니다

## 기본 구조

```text
제목 한 줄

짧은 문제 제기

블로그에서 압축한 통찰

실무자가 가져야 할 관점

실무 판단 기준 한 줄

블로그 링크
```

중요 규칙:

- `[후츠릿 인사이트]`, `후츠릿의 인사이트` 같은 라벨을 쓰지 않는다.
- "저는 여기서 ..."로 설명하지 말고, 관점 자체가 문장에 드러나게 쓴다.
- "중요합니다", "필요합니다"를 반복하지 않는다.
- 제목은 맨 위에 간결하게 한 줄로 쓴다.
- 첫 문장은 설명형으로 시작하지 않는다. `같은 모델인데`, `문제는`, `차이는`, `프롬프트가 아니라` 같은 대비로 멈추게 만든다.
- 본문은 블로그 내용을 그대로 요약하지 말고, 최신 기술/사건에서 얻은 통찰을 압축한다.
- 중간에는 실무자가 바로 가져갈 판단 기준을 한 줄로 넣는다.
- 목표는 LinkedIn에서 블로그 전문으로 유입시키는 것이다.
- 마지막에는 블로그 링크 자리를 넣는다. 아직 배포 전이므로 `[블로그 링크]` 자리표시자를 사용한다.
- `블로그 전문:`처럼 불필요한 콜론을 쓰지 않는다.
- 해시태그는 3~5개만 쓴다.
- 이모지는 전체 2~4개 안쪽으로 제한한다.
- 제목 또는 첫 문장에 이모지 1개를 사용할 수 있다.
- 체크리스트, 변화 단계, 블로그 링크 유도에만 제한적으로 쓴다.
- 문장마다 이모지를 붙이지 않는다.
- 이모지는 가독성 보조용이며, 전문성과 실무 감각을 해치면 쓰지 않는다.

## 패턴 1. 사건에서 기준 뽑기

사용 조건:

- 뉴스 기사, 사건, 실제 사례가 입력으로 들어온 경우

구조:

```text
🔍 [사건 한 줄]

겉으로 보면 A처럼 보입니다.
하지만 이 사건의 핵심은 B입니다.

AI 시대에 중요한 건 [도구명] 자체가 아니라
[설계/검증/운영/오케스트레이션] 능력입니다.

결국 [한 문장 결론].
```

## 패턴 2. 패러다임 변화 선언

사용 조건:

- AI 엔지니어링, 에이전트, 개발 방식 변화처럼 흐름을 정리해야 하는 경우

구조:

```text
🚀 [지금 업계에서 바뀌는 것 한 문장]

같은 도구를 쓰는데
어떤 사람은 10배 빠르고
어떤 사람은 제자리입니다.

차이는 더 좋은 프롬프트가 아니라
[환경/컨텍스트/하네스/시스템] 설계입니다.

[연도 또는 단계별 변화]

2023 - ...
2025 - ...
2026 - ...

이제 필요한 역할은
"AI에게 잘 말하는 사람"이 아니라
"AI가 반복해도 올바르게 일하게 만드는 사람"입니다.
```

## 패턴 3. 역할 재정의

사용 조건:

- 개발자, 강사, 1인 기업, 크리에이터의 역할 변화를 말할 때

구조:

```text
우리는 더 이상 [기존 역할]만 하는 사람이 아닙니다.

AI가 실행을 맡기 시작하면
사람에게 남는 일은 [새 역할]입니다.

중요해지는 역량은 세 가지입니다.

1. ✅ [역량]
2. 🧩 [역량]
3. ⚠️ [역량]

앞으로 차이는 도구 사용량이 아니라
시스템을 설계하고 검증하는 능력에서 날 것입니다.

🔗 블로그 전문 [블로그 링크]
```

## 작성 기준

- 300~800자를 기본으로 한다.
- 문단은 짧게 쪼갠다.
- 한 문장에 개념을 여러 개 넣지 않는다.
- 단순 정보보다 판단과 관점을 우선한다.
- "AI가 다 해준다"보다 "사람이 무엇을 설계하고 검증해야 하는가"를 강조한다.
- 필요할 때만 체크리스트, 연도별 변화, 단계 구분을 사용한다.
- 후킹은 과장보다 대비로 만든다.

```text
같은 모델, 같은 프롬프트인데 결과는 10배 갈린다.
문제는 프롬프트가 아니라, AI가 일하는 구조다.
AI에게 일을 맡기는 순간 병목은 질문이 아니라 운영이 된다.
```
